## Source reviewed

Reviewed the complete working changes in `lib/calculators.ts`, `lib/calculator-families.ts`, `lib/calculator-personal.ts`, `lib/calculator-specialists.ts`, `app/calculators/calculator-experience.tsx` and `app/calculators/calculator-presentation.ts`, together with the new mode fixtures/regressions and test-runner adjustments. The final filename and lint cleanups were inspected after the substantive review. No application source was edited by this reviewer.

- **Travel methods now agree with their inputs and outputs.** Actual-cost mode uses established qualifying costs and the matching business/total-distance ratio, retains the allowance cap and record gate, and does not demand or display deemed vehicle/day/fuel/maintenance components. Hidden deemed facts do not affect the actual result or export. Deemed mode retains its reviewed tables, costs-borne conditions, day convention and gazetted source. The reviewer independently opened the current [SARS travel logbook guidance](https://www.sars.gov.za/types-of-tax/personal-income-tax/travel-e-log-book/), which distinguishes these two methods. The app still requires independently established qualifying actual costs; it does not determine expense eligibility or statutory restrictions from raw expenditure.
- **Net-raise wording matches the existing solver.** The target is an additional take-home amount in raise mode and a total take-home amount in absolute mode. Form labels, error summaries, comparisons and exported input labels retain that meaning. Monthly/annual zero and positive raise cases preserve the one-cent inverse tolerance.
- **Mode metadata is consistent across the experience.** Retirement/TFSA growth and hourly gross conversion are independent financial scenarios. Tax modes retain the applicable year and result meaning. Controls, provenance, packs, comparison gating and filenames no longer attach an unused assessment year to a growth calculation. Year-dependent comparisons require an explicit cross-year selection; comparison JSON preserves the appropriate assessment/rule year and period. The new shared context function is called after module initialization; the inspected import cycle does not introduce an initialization-time access failure.
- **Missing answers and unsupported facts remain distinct.** Blank active required fields produce invalid outcomes with actionable linked field errors. Explicit uncertainty remains a scope blocker rather than an assumed favourable answer. Valid zero values, optional unknown refund amounts, and the established UIF daily-only boundary remain covered by regressions.
- **The small-item condition belongs to its election.** Ordinary straight-line wear-and-tear no longer requires standalone-small-item facts. The immediate election still requires its affirmative standalone condition and a cost strictly below R7,000. Other asset/eligibility/date restrictions remain intact. The existing strict-schema test was correctly narrowed to active example fields, with separate tests retaining the small-election requirements.
- **Final cleanup does not alter tax behavior.** The source helper rename, stable category-icon component and removal of unused symbols preserve behavior. Empty official-source sections are omitted for arithmetic-only outcomes. The download filename uses the selected mode's year sensitivity.

No authentication, saved-preparation scope, persistence, database migration, dependency-version, sharing or paid-service change is included.
